# TUTI Games — лендинг

Односторінковий сайт-візитівка студії дитячих ігор. Українська мова,
Next.js на App Router.

## Стек

| Що | Навіщо |
| --- | --- |
| [Next.js](https://nextjs.org) 15, App Router | Серверні компоненти, `next/image` для картинок |
| [Tailwind CSS](https://tailwindcss.com) 4 | Стилі; усі токени — в одному `@theme` у `app/globals.css` |
| `@fontsource-variable/nunito` | Шрифт локально, один змінний файл із кирилицею |
| Python + Pillow | Скрипт підготовки графіки. Лише на етапі розробки |

Свого клієнтського коду — один компонент `SiteScripts`: поява блоків
при скролі та шапка з мобільним меню. Більше нічого інтерактивного немає.

## Команди

```bash
npm install
npm run dev      # http://localhost:3000
npm run build
npm start
npm run format   # Prettier
```

## Редагування

**Текст** — тільки `content/site.ts`, статті — `content/articles.ts`.
Розмітку чіпати не треба.

**Кольори, шрифт, рух** — блок `@theme` у `app/globals.css`.

**Обкладинки** — у `site.ts` вказується ім'я файлу без розширення
(`cover: "borsch-01"`). Помилка в імені зупиняє збірку зі списком
доступних назв.

**Нова графіка** — покласти файли в потрібну теку `_source` і запустити:

```bash
pip install pillow numpy
python scripts/prepare-assets.py
```

Скрипт обрізає інтерфейс Procreate з кадрів, ріже широкі, вирізає
персонажів із рівного тла в прозорий WebP, нормалізує іконки соцмереж
під `currentColor` і перетискає ілюстрації. Дрібну графіку з `faces/`
і `decor/` зрізає по альфі — інакше невидимі поля не дали б притиснути
наклейку до краю картки. Нові файли треба дописати в `content/images.ts`
— імпорти там явні.

## Статті

Тіло статті — не HTML, а список блоків (`p`, `h2`/`h3`/`h4`, `ul`, `ol`,
`quote`). Коли статті почнуть приходити з адмінки, віддавати такий
список простіше й безпечніше, ніж домовлятися про дозволений HTML.

Якорі заголовків і зміст рахує одна функція `prepare()` за один прохід.
Якби зміст і текст рахували їх окремо, при двох однакових заголовках
списки розійшлися б, і пункт вів би не туди.

Сторінка всіх статей фільтрує список у браузері, тож картки їдуть
у клієнтський бандл. Їм передається `toCard()` — рівно те, що видно на
картці. Якби передавали самі статті, у бандл поїхали б і всі їхні
тексти, і з кожною новою статтею він би ріс.

Пошук шукає по заголовку, опису й темах — не по тілу статті, саме
з цієї ж причини.

Стрічка тем гортається вбік, коли тем більше, ніж влазить у рядок.
Смуга прокрутки схована, а про запас із боків каже розчинення краю
(`.tag-scroller` + `mask-image`). Вмикає його JS: чистим CSS не
дізнатися, чи докрутили вже до краю.

Тягнути стрічку мишкою теж можна. Зроблено навмисно без
`setPointerCapture`: захоплення перенаправляє подальший `click` на
саму стрічку, і кнопки тем усередині перестають натискатися. Тому рух
і відпускання слухаються на вікні, а `click` після перетягування
глушиться — інакше кожне тягання закінчувалося б випадковим вибором
теми під курсором.

Курсив у цитатах — окремий файл шрифта (`wght-italic.css`). Браузер
тягне його лише там, де курсив справді трапиться, тож на сторінках без
цитат це нічого не коштує. Синтетичний нахил вийшов би дешевшим, але
помітно гіршим.

## На що варто зважати

**Шрифт.** Nunito, один змінний файл, повна кирилиця разом з «ґ».
Заголовки — 800, текст — 400/600. Браузер бере лише latin і cyrillic,
це 59 KB на два файли.

Якщо мінятимете шрифт — перевіряйте дві речі. Чи є в ньому кирилиця:
Outfit, Fredoka, Baloo та більшість «дитячих» шрифтів мають тільки
латиницю, і українська мовчки поїде на системний. І чи виставлені
`unicode-range`: у японських шрифтів (M PLUS Rounded 1c) fontsource їх
не ставить, і браузер тягне всі підмножини — це 259 правил `@font-face`
і 310 KB CSS.

**Емодзі й стрілки** навмисно віддані системному шрифту, а стрілка в
кнопці намальована SVG: текстовий символ «→» не входить у latin-підмножину
й тягнув би окремий файл шрифта заради однієї гліфи.

**Перший екран** анімується не спостерігачем, а звичайною анімацією:
його видно одразу, чекати нема чого. Заголовок виростає з центру,
картинка — знизу вгору, декор докручується до свого кута. Кут задає
`--deco-tilt` просто в розмітці.

**Наклейки на кутах** висять поза блоком, який їх обрізає: у сітці ігор
і в кар'єрі картинка лежить у власному `overflow-hidden`, а наклейка —
сусідній елемент у спільній `relative`-обгортці. Ті, що прив'язані до
слова в заголовку, зсунуті від'ємним `margin`, а не `translate`:
`transform` там зайнятий анімацією появи.

Виліт наклейки за край блоку заданий по брейкпойнтах, і це навмисно:
поки сітка впирається в поля секції, великий виліт просто зрізало б
`overflow-hidden`. Ширші відступи вмикаються там, де поля вже є
(`2xl:` у героя, `min-[1440px]:` у сітці ігор). Міняючи ці відступи,
перевіряйте вузькі ширини: `body` має `overflow-x: hidden`, тож зайвий
виліт не дає горизонтальної прокрутки — його просто зрізає, і в коді
це ніяк не видно.

Самі наклейки готуються до 1100 px, а не до 512: на сторінці вони
показуються до ~220 CSS-пікселів, і на екранах 2x цього вже мало.
`quality={90}` на них теж не випадкове — дефолтні 75 на дрібній
графіці з чіткими контурами дають помітне мило.

**Іскри за курсором** створює `SiteScripts` — не частіше ніж раз на
80 мс і не ближче ніж за 30 px від попередньої, інакше за мишкою
тягнеться суцільна смуга. На тачскрін не вмикаються: там `pointermove`
приходить під час скролу.

**Курсори.** П'ять намальованих кадрів замість системних: стрілка
(звичайний), палець із зірочками (усе клікабельне), палець із
променями (натиснуто), палець зі знаком (вимкнений контрол), розкрита
долоня (стрічку тем можна тягнути).

Простий палець без зірочок лежить у `_source/cursors/pointer.png` і
зараз не використовується — щоб повернути, досить рядка в
`CURSOR_SPECS` і посилання в CSS.

Розміри й гарячі точки живуть у `CURSOR_SPECS` у `prepare-assets.py`,
а в `globals.css` повторені числами — `cursor` не вміє відсотків, тож
міняти доводиться в обох місцях. Ширини підібрані так, щоб сама
рукавичка була однакова: у кадрах із зірочками чи знаком вона займає
меншу частку висоти.

`image-set` стоїть другим оголошенням, а не єдиним: браузери без нього
лишаються на першому рядку й отримують звичайний 1x, а не порожній
курсор. Усе загорнуто в `pointer: fine` — на телефоні курсора немає,
і без цього він тягнув би PNG ні для чого.

Поле вводу свідомо лишилося з системною «паличкою»: кадру під неї
немає, а рукавичка заважала б цілитися між літерами.

**Анімація появи** двобічна — блок згортається, коли йде з екрана.
Спостерігач стежить за зовнішньою секцією, а не за анімованим шаром:
трансформація зсуває рамку елемента, і спостереження за ним самим дає
блимання на межі екрана.

**Статичний експорт.** Зараз `next/image` ресайзить картинки на сервері.
Для чистої статики без Node у `next.config.mjs` є закоментований
`output: "export"` — разом із `images: { unoptimized: true }`. Ціна:
на телефон поїдуть повнорозмірні кадри.

## Що ще треба від клієнта

Позначено як `TODO` у `content/site.ts`:

- домен (потрібен для canonical, OG і sitemap);
- пошта й соцмережі;
- фінальні назви застосунків і як 10 міні-ігор по них розподілені;
- справжні новини для блоку «Що в роботі» замість опису робіт;
- вакансії (зараз показується блок «надішліть портфоліо»);
- OG-зображення 1200×630 і фавікон;
- сторінки політики приватності й умов використання;
- **справжні статті**: чотири матеріали в `content/articles.ts` написані
  нами як заглушки, а імена авторів вигадані. Поки їх не замінять,
  сайт приписує тексти людям, яких не існує.

П'ять міні-ігор ще без власної графіки — для них у сітці стоять
ілюстрації, позначені `placeholderArt: true`.
