# Порти сайту

Той самий лендинг у трьох варіантах. Основний — Astro в корені репозиторію,
тут лежать два перенесення.

| | де | що треба для запуску |
| --- | --- | --- |
| Astro (основний) | корінь репозиторію | Node |
| Ванільний | `ports/vanilla` | нічого |
| Next.js | `ports/next` | Node |

## Наскільки точно збіглося

Порівняння — покадрове, знімок усієї сторінки в тому самому браузері.

| | десктоп 1440 | телефон 390 |
| --- | --- | --- |
| **Ванільний** | 0 пікселів різниці з 13.3 млн | 0 пікселів |
| **Next.js** | геометрія збігається точно, середня різниця 1.0/255 | те саме, 0.9/255 |

У Next різниця не у верстці: висота сторінки, положення й розміри всіх
секцій збігаються до пікселя, вертикального зсуву немає. Відрізняються
самі пікселі картинок — Astro й Next стискають WebP різними
налаштуваннями. При збільшенні у 2 рази видно тільки те, що Next трохи
різкіший. Зникає, якщо віддавати обом однакові готові файли.

Поведінку перевірено окремо в обох портах:

- поява блоків при скролі, двобічна (розкривається вниз, згортається вгору);
- шапка стає білим «острівцем» після скролу;
- картки застосунків наїжджають одна на одну й повністю читаються
  на екрані 390×667.

## Вага першого завантаження

Свіжий профіль браузера, кеш вимкнено, десктоп 1440.

| | разом | з чого |
| --- | --- | --- |
| Astro | 275 KB | картинки 196, шрифти 59, CSS 7.4 |
| Ванільний | 275 KB* | те саме |
| Next.js | 383 KB | картинки 179, **скрипти 113**, шрифти 59, CSS 7.4 |

\* У заміру ванільна версія показала 368 KB, але це артефакт тестового
сервера: `python -m http.server` нічого не тисне, а HTML і CSS у ній
лежать нестиснені для читабельності. Під gzip вони дають 19.5 KB проти
112 KB «як є» — тобто на реальному хостингу цифра збігається з Astro.

113 KB скриптів у Next — це React. Без нього App Router не працює.
У двох інших версіях свого JS 1.4 KB.

## Ванільний — `ports/vanilla`

Самодостатня тека: `index.html`, `styles.css`, `main.js`, `assets/`.
Жодної збірки, жодних залежностей. Кидається на будь-який хостинг як є.

```bash
# подивитися локально
cd ports/vanilla && python -m http.server 4340
```

**Як зроблено.** Тека збирається скриптом зі зібраної Astro-версії:

```bash
npm run build && python scripts/export-vanilla.py
```

Скрипт розкладає збірку на читабельні файли: виносить CSS і скрипт
окремо, перейменовує картинки з хешованих імен на людські
(`hero-tuti-1152.webp` замість `hero-tuti.rERdPp50_Tdild.webp`),
переписує всі посилання й проганяє результат через Prettier.

Береться саме збірка, а не вихідники: так верстка збігається точно,
без ризику розійтися при ручному переписуванні. Далі тека живе
самостійно — правити її можна руками, перегенерація не потрібна.

**Що варто знати:**

- `styles.css` згенерував Tailwind. Це звичайний CSS і працює без
  нічого, але класи в ньому утилітарні (`.mt-3`, `.bg-sky`). Щоб додати
  новий клас, його треба дописати в CSS руками — сканера тут уже немає.
- `main.js` написаний від руки й прокоментований, це не мініфікований
  вивід. Той самий код, що в Astro-версії, лише без TypeScript.
- Контент лежить прямо в розмітці. У Astro-версії десять плиток ігор,
  чотири застосунки й чотири новини генеруються циклами з `site.ts` —
  тут це розгорнутий HTML, і правка тексту стає правкою верстки.

## Next.js — `ports/next`

Повноцінний вихідник на App Router. Структура повторює Astro-версію
один в один.

```bash
cd ports/next
npm install
npm run dev     # http://localhost:3000
npm run build && npm start
```

**Як лягло:**

| Astro | Next |
| --- | --- |
| `.astro`-компонент | серверний `.tsx`, без хуків |
| `<Image>` з `astro:assets` | `next/image` |
| `<picture>` з двома кадрами | `getImageProps()` — Next саме для цього його й дає |
| `import.meta.glob` | явні імпорти в `content/images.ts` |
| два інлайн-скрипти | один `"use client"` компонент `SiteScripts` |
| `site.ts`, `tones.ts`, `global.css` | перенесені без змін |

`content/site.ts` і `content/tones.ts` — побайтові копії. Правки контенту
робляться так само, як і в основній версії.

**Ціна переїзду.** Свого JS у Astro-версії 1.4 KB. Тут перше
завантаження тягне 111 KB — це React-рантайм, без нього App Router не
працює. Для лендингу без інтерактиву це чистий програш у тій метриці,
заради якої ми оптимізували шрифти й картинки.

**Про статичний експорт.** Зараз `next/image` ресайзить картинки на
сервері, як це робила Astro. Якщо треба чиста статика без Node — у
`next.config.mjs` є закоментований `output: "export"`. Разом із ним
доведеться поставити `images: { unoptimized: true }`, і на телефон
поїдуть повнорозмірні кадри. Тоді має сенс нарізати розміри заздалегідь
скриптом, як це робить `scripts/prepare-assets.py`.

**Спільні ассети.** `ports/next/assets` — копія `src/assets` з основного
проєкту. Якщо перемальовуєте графіку, спершу проганяйте
`python scripts/prepare-assets.py` у корені, потім копіюйте теку сюди.
